# Guide: How to Add or Edit Documentation Pages

This guide is for an AI agent (or any contributor) making changes to the Vajra documentation site.

The site is built with **Docusaurus v3** (upgrading toward v4 compatibility).
All documentation content lives in `website/docs/`.
The sidebar is **auto-generated** from the filesystem — no manual sidebar configuration is needed for normal edits.

---

## Project Layout (relevant parts only)

```
website/
├── docs/                        ← All documentation content lives here
│   ├── intro.md                 ← The first page shown under /docs
│   ├── tutorial-basics/
│   │   ├── _category_.json      ← Controls the sidebar group label and position
│   │   └── *.md                 ← Pages inside this group
│   └── tutorial-extras/
│       ├── _category_.json
│       └── *.md
├── sidebars.ts                  ← Set to autogenerated — do not touch unless explicitly asked
├── docusaurus.config.ts         ← Site-level config (title, navbar, etc.) — do not touch unless explicitly asked
└── src/                         ← Custom React components and CSS — do not touch unless explicitly asked
```

---

## Rule 1: Every documentation file must start with a frontmatter block

Frontmatter is the `---` block at the very top of a Markdown file. Docusaurus reads it before rendering.

```md
---
sidebar_position: 2
sidebar_label: 'My Page'   ← Optional. If omitted, Docusaurus uses the H1 heading as the label.
---

# My Page Heading

Content starts here.
```

**`sidebar_position`** — controls where this page appears within its parent group in the sidebar. Lower number = higher up. Always set this explicitly to avoid alphabetical ordering surprises.

**`sidebar_label`** — optional override for the text shown in the sidebar. If omitted, the H1 heading of the page is used.

---

## Rule 2: File name becomes the URL slug

A file at `docs/getting-started/installation.md` becomes `/docs/getting-started/installation`.
Use lowercase, hyphen-separated names. No spaces.

---

## How to Edit an Existing Page

1. Open the `.md` or `.mdx` file under `website/docs/`.
2. Edit the content below the frontmatter block using standard Markdown.
3. Do not change `sidebar_position` unless reordering is explicitly requested.
4. Do not change the file name unless renaming is explicitly requested (it changes the URL).

---

## How to Add a New Page

1. Decide which group (folder) the page belongs to, or place it at the root of `docs/` if it is top-level.
2. Create a new `.md` file with a lowercase, hyphen-separated name.
3. Add frontmatter at the top. Set `sidebar_position` to a number that places it correctly among its siblings.
4. Write the page content in Markdown below the frontmatter.

**Example — adding a new top-level page:**

File: `website/docs/architecture.md`

```md
---
sidebar_position: 3
---

# Architecture

Describe the architecture here.
```

## How to Add a New Category (Group of Pages)

1. Create a new folder inside `website/docs/` with a lowercase, hyphen-separated name.
2. Create a `_category_.json` file inside that folder.
3. Add your `.md` files inside that folder.

**`_category_.json` format:**

```json
{
  "label": "Human-Readable Group Name",
  "position": 3,
  "link": {
    "type": "generated-index",
    "description": "One-sentence description shown on the group's index page."
  }
}
```

- **`label`** — the text shown in the sidebar for this group.
- **`position`** — where this group appears relative to other top-level groups and pages.
- **`link`** — the `generated-index` type auto-generates a landing page for the group listing all its pages. Remove the `link` key entirely if you don't want a landing page for this group.

## Markdown Features Available

Standard Markdown plus:

- **Admonitions** (callout boxes):

  ```md
  :::note
  This is a note.
  :::

  :::warning
  This is a warning.
  :::

  :::tip
  This is a tip.
  :::
  ```

- **Code blocks with language highlighting and title:**

  ````md
  ```python title="example.py"
  def hello():
      print("Hello, world!")
  ```
  ````

- **MDX** (`.mdx` extension): allows importing and using React components inside Markdown. Only use `.mdx` if the page requires a React component — otherwise use `.md`.

---

## What NOT to Touch

Unless the task explicitly requires it, do not edit:

- `website/sidebars.ts` — the sidebar is autogenerated; editing this file manually overrides autogeneration and creates maintenance overhead.
- `website/docusaurus.config.ts` — site-level config (URL, navbar, footer, plugins).
- `website/src/` — custom React components and CSS.
- `website/static/` — static assets (images, fonts, etc.) unless adding new images for a doc page.

---

## Checklist Before Finishing

- [ ] Every new `.md` file has a frontmatter block with `sidebar_position` set.
- [ ] Every new folder has a `_category_.json` with `label` and `position` set.
- [ ] File names are lowercase and hyphen-separated.
- [ ] No existing `sidebar_position` values were changed unless reordering was explicitly requested.
- [ ] No file was renamed unless renaming was explicitly requested.
